# Examples

Three sites in [`examples/`](https://github.com/lea-m-hadzic/docs-studio/tree/main/examples),
generated by `init` and then written, kept in the repository so the output can be read
without generating anything.

All three are **fictional projects**. Nothing on them is a real API, result or
publication. The third is the point of the set: it is nothing like the two research
sites the design language came from, and it needed no code change to produce.

| Site | Profile | Palette | Branding | Pages |
| --- | --- | --- | --- | --- |
| `tidepool` | `python` | `ocean-violet` | generated monogram | 8 |
| `Lattice.jl` | `julia` | `indigo-lavender` | supplied SVG, dark variant, favicon | 8 |
| `greenline` | `generic` | `neutral` | monogram, custom initials | 8 |

Each checks clean and builds under `--strict`.

## `tidepool` — a Python package

A measurement-logging library. Exercises the `python` profile: `python` and `bash`
fences, an API page of signatures, a schemas page of dataclass fields, a citation page.

```bash
docs-studio init tidepool \
  --name tidepool \
  --description "Reproducible sampling and aggregation for long-running measurement runs" \
  --author "Example Lab" \
  --site-url https://example.github.io/tidepool/ \
  --repo-url https://github.com/example/tidepool \
  --language python --preset ocean-violet \
  --resource "GitHub Repository|https://github.com/example/tidepool|simple-github" \
  --resource "Example dataset|https://example.org/tidepool-data|material/database-outline" \
  --yes
```

It also shows the ordinary workflow after `init`: pages were added to `[[nav]]` and
picked up starter pages from [`update`](update.md).

## `Lattice.jl` — a Julia package

Lattice sums on periodic structures. Exercises the `julia` profile and the paths the
other two do not:

- a **supplied logo** with a dark variant, so the CSS swap is live
- a **supplied favicon**
- **display equations** in the `.ds-math` block — Unicode in a styled frame, no maths
  renderer and so no third-party request

```bash
docs-studio init Lattice.jl \
  --name Lattice.jl \
  --language julia --preset indigo-lavender \
  --logo brand/lattice-mark.svg \
  --logo-dark brand/lattice-mark-dark.svg \
  --favicon brand/lattice-favicon.svg \
  --yes
```

Note what the `julia` profile does and does not do. It changes the starter wording — it
knows `Pkg.add` is the first thing a reader will try, so the install page says outright
when a package is not registered — and it expects `julia` fences. It does **not** parse
them: there is no Julia parser in the standard library, and guessing with a regular
expression would produce false errors. See [Validation](validation.md).

## `greenline` — not a research project at all

A route planner for a city's protected bike lanes, maintained by volunteers. No API
page, no citation page, a Contributing section, an FAQ, and `trigger = "push"` instead
of manual deployment.

```bash
docs-studio init greenline \
  --name Greenline \
  --description "A route planner for the city's protected bike lanes" \
  --author "Greenline Volunteers" \
  --language generic --preset neutral --trigger push \
  --yes
```

It also demonstrates regenerating a monogram with different initials: `Greenline` gives
`GR` by default, so `branding.monogram_text = "GL"` was set, the generated marks were
deleted, and `update` drew them again. See
[Logo and favicon](branding.md#the-generated-monogram).

## Building one

```bash
pip install "zensical==0.0.67"
cd examples/tidepool
docs-studio check
zensical serve
```

## What they are for

They are regression tests as much as documentation. Continuous integration checks all
three on every push, so a change to a template that breaks a real site fails there
rather than in somebody's repository.
